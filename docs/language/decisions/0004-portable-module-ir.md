# 0004: Portable module compilation boundary

Status: accepted, initial implementation; amended by [0045](0045-lair-method-refinement-and-facility-allocation.md)

Complete Lab modules compile first to verified portable module IR. This boundary contains resolved imports, checked declaration properties, structured nominal and union types, typed expression trees, explicit workflow signatures and state, resolved operation identities, operand ownership modes, checked outcome constructors, control-flow continuation, and reactive handler structure. The checked schema retains direct action-capability metadata for frontend compatibility, but production planning does not consume it: [0045](0045-lair-method-refinement-and-facility-allocation.md) makes Capability requirements products of Method refinement.

Portable module IR is intentionally independent of any facility. Producing verified module IR means frontend type, return, and affine material-flow checks have passed for the supported control-flow subset. It does not mean that a workflow has been scheduled, that a facility contains qualified offerings and configured adapters for every requirement, or that any command has been durably dispatched. Those are later planning and runtime boundaries and must have distinct outputs.

`CheckedModule` is the sole source-compilation boundary. Source lowering consumes it exactly once to construct verifier-valid LAIR. Narrow specializations consume LAIR—not `CheckedModule`—and select only the properties and resolved operations they support; output selection never switches to a different source frontend or bypasses LAIR. Lower IRs must preserve the workflow, event, evidence, dependency, and material semantics required by their backend rather than reconstructing them from source text.

Source lowering constructs Design and method-neutral Intent or Workflow LAIR. Design operations are strictly declarative and do not carry procedure data. Intent operations preserve reachable source actions, material ownership edges, artifact dependencies, control structure, source identity, and requested policy. Method refinement replaces refinable Intent operations with verifier-valid candidate regions containing Procedure operations and first-class Capability requirements. It enumerates applicable facility-independent methods but does not select an unpinned method before facility planning.

Facility planning extracts one global constraint problem from verified method alternatives and selects methods, exact capability offerings, Assets, adapters, MaterialLots, movements, and scheduling together. The complete solution is applied back to LAIR, producing an Allocated Procedure stage from which immutable adapter invocations are projected. Neither planning nor adapters may recreate a parallel biological recipe IR. The reviewed plan freezes the selected method and every physical binding. Hardware constants and rendering logic do not belong in the portable AST, checked IR, facility-independent LAIR, or generic output module.
